# Закрыть пробелы в «Молчаливых поломках»

## Overview
- В `docs/design.md`, раздел «Молчаливые поломки», пять пунктов помечены **пробел**: защиты нет, хотя тест возможен. Закрыть их тестами или честно переписать пункт.
- Готово, когда: ни один пункт раздела не помечен **пробел**; каждый новый или изменённый тест падает на названной мутации (проверено вручную); `make check`, `make cov`, `make mutants` зелёные.

## Context (from discovery)
- Раздел перестроен по слоям с пометками «→ что ловит»; правило — в `CLAUDE.md`. Эти правки ещё не закоммичены и едут в ветке этого плана.
- Пробелы: `Solid` собирает пассажиров до движения (`engine/src/physics/solid.rs:37`), push/carry без остатка (`solid.rs:66–78`), ложное пересечение заметаний (`engine/src/physics/actor.rs:98–124`), нет аллокаций в колбэке (`engine/src/audio/mixer.rs:112`, `engine/src/audio/mod.rs:105`), отброс без кражи (`mixer.rs:136–144`).
- Решения согласованы с codex (тред `silent-gaps`), план проверен агентом plan-review.

## Development Approach
- **testing approach**: TDD; тест сначала прогоняется против мутации (временная правка кода), потом — против исходного кода.
- Пометка пункта в `docs/design.md` меняется в той же задаче, что и его тест.
- Следующая задача — только при зелёном `make check`.

## Solution Overview
- Пассажиры: снимок до движения отличается от пересчёта перед осью только у диагональной платформы — при заблокированном carry по X или при новом пассажире после сдвига по X. Платформы платформера одноосные (`games/platformer/src/main.rs:520`, `:536`), различие не наблюдаемо. Тест на диагональ закрепил бы произвольный выбор, поэтому пункт переписывается с пометкой «будущее: диагональные платформы».
- Заметание: движковый тест L-пути ловит заполнение прямоугольника вокруг пути одного тела. Утверждение пункта про два тела проверяет только игровой сценарий: враг движется раньше игрока, сенсоры строятся после (`main.rs:736–743`).
- Аллокации: свой `GlobalAlloc` требует `unsafe` — запрещено; `assert_no_alloc` под BSD-1-Clause — нет в `deny.toml`. Dev-зависимость `allocation-counter 0.8.1` (MIT/Apache-2.0) сама ставит глобальный аллокатор только в тестовый бинарник lib `engine`, счёт поточный, провал — обычный `assert`. Блокировки и I/O не ловит — ревью.
