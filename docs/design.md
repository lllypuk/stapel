# Дизайн движка

## Цель

Универсальный движок: сначала 2D, потом 3D. Каждая функция движка появляется только тогда, когда она нужна конкретной игре из `games/`. Без игры-потребителя архитектура растёт вслепую.

## Решения

| Решение | Почему |
|---|---|
| Rust | безопасная память, cargo, `wgpu` |
| Готовое: `winit`, `wgpu`, `glam`, `image`, `cpal`, `hound`, `lewton`, `fontdue` | платформа и форматы — не движок; месяцы на драйверы и парсеры ничему не учат |
| Своё: цикл, рендер, ECS, ресурсы, физика, микшер | это и есть движок |
| ECS и хэндлы вместо ссылок между объектами | граф объектов со ссылками упирается в borrow checker |
| Рендер на GPU с камерой-матрицей с первого дня | 3D добавляется перспективой, мешами и глубиной без переписывания |

## Структура

Cargo workspace: `engine/` (библиотека), `games/<имя>/` (бинарники). Движок не знает об играх.

Слои снизу вверх: платформа → цикл и время → рендер → ресурсы → мир (ECS) → физика → звук.

## Цикл

- `winit` владеет циклом событий, поэтому движок — фреймворк, а игра реализует трейт `Game { init, update, draw(alpha) }`.
- Симуляция — фиксированный шаг 60 Гц, отрисовка — свободная, с интерполяцией по `alpha`. `dt` за кадр ограничен 250 мс.
- Порядок тика: ввод → логика → физика → события коллизий → отложенное удаление сущностей.

## Рендер

- Immediate-mode API `draw_sprite(...)`: вызовы копятся на CPU, сортируются по `(слой, текстура)` и рисуются через instancing. Новый draw call — только при смене текстуры.
- Рендер не знает об ECS: система спрайтов кормит тот же батчер.
- `Gfx::draw_sprite(Sprite { texture, pos, size, rotation, uv, color, layer })` — прямоугольник с центром в `pos`, повёрнутый на `rotation` против часовой, с UV-подпрямоугольником `uv` (доли текстуры, `(0, 0)` — левый верхний). Литералы — через `..Default::default()`: белый tint, вся текстура `WHITE`. `cos/sin` считаются на CPU, в шейдере поворот геометрии отдельно от UV.
- Мир фиксированного размера (`Camera2D { center, size }`, Y вверх) вписывается в окно с полями (`letterbox`): поле игры не зависит от пропорций окна. Поля — цвет `clear_color`, `set_viewport` ограничивает только геометрию.
- Пиксель-арт (`Config::pixel_perfect`) — `letterbox_pixel`: масштаб `floor(min(W/w, H/h))`, отступы — целая половина остатка; окно меньше мира — дробный `letterbox`. Камера и края всех спрайтов — на целых мировых пикселях: позиция `round(lerp(prev, cur, alpha))` с одним `alpha` на кадр, центр спрайта нечётного размера — на `.5`. Тогда швов атласа нет без экструзии тайлов.

## ECS

- Сущность = индекс + поколение.
- Хранение — sparse set; архетипы, только если профайлер покажет, что запросы — узкое место.
- Хранилища в `RefCell`: конфликт `&mut` даёт панику, а не UB.
- `World`, компоненты и системы принадлежат игре: `World` в структуре игры, не в `Context`. `Transform` в движок не переезжает: тела платформера (целые AABB) и Asteroids (f32 с углом) разные.
- Системы — методы игры по порядку тика, обход одного хранилища + `get` в другом. Параллельный планировщик, запросы на трейтах кортежей и иерархия — когда понадобятся.

## Ресурсы, физика, звук

- `Handle<T>` — индекс, кэш «путь → хэндл». Отсутствующий файл заменяется заглушкой и пишется в лог; заглушка тоже кэшируется по пути.
- Поколения в хэндле нет, пока нет выгрузки: индексы append-only на всём сроке `Assets` и GPU-таблицы. Первое переиспользование слота обязано ввести поколение, иначе старый хэндл молча рисует чужой ресурс.
- Шрифт: `load_font(path, px)` растеризует ASCII 32..=126 через `fontdue` в атлас покрытия, кэш по `(path, px)`. Ошибка — `warn` и заглушка без атласа: глифы — белые прямоугольники.
- Физика — целочисленная модель Celeste: свободные функции над `Tilemap` и срезами тел игры, о `World` не знает. `Actor` движется шагами по 1 px (X, потом Y) с дробным остатком — без туннелирования и застревания, пока старт свободен. `Solid` проходит сквозь тайлы, толкает пересечённых и везёт стоящих сверху `Actor`.
- Триггеры — сенсоры, проверяемые на каждом пиксельном шаге: известны ось и направление входа. Заметённые AABB не используются.
- Отложены: круг, сетка для динамических тел (их десятки — перебор), слои и маски, события enter/exit, динамические тела.
- Звук: колбэк `cpal` в потоке реального времени, команды через lock-free очередь `rtrb`, эффекты декодируются в память целиком.

## Молчаливые поломки

- Флаги ввода «только что» сбрасываются после первого тика кадра, а не после кадра: за кадр бывает 0 или 2 тика.
- Удаление сущности во время обхода — только через буфер команд.
- До `apply` удалённая сущность ещё видна в обходе: две пули в один астероид за тик дали бы двойные очки и раскол, пуля и корабль — ещё и потерю жизни. Пара срабатывает, только если ни одна из сущностей не ждёт удаления (`Commands::is_pending`), и обе ставятся в очередь вместе.
- Без поколения в ID устаревшая ссылка указывает на новую сущность.
- Вставка компонента в слот мёртвой сущности даёт призрачную сущность в обходе: `World::insert` паникует на мёртвую `Entity`, а `SparseSet::insert` закрыт от игры.
- sRGB: текстуры цвета и поверхность — `*Srgb`, данные — линейные. Иначе цвета искажаются без ошибки.
- Premultiplied alpha, иначе на краях спрайтов тёмная кайма.
- Премультипликация — в линейном пространстве: sRGB → linear → ×α → sRGB, α без гаммы (белый при α = 128 хранится как 188). Умножение прямо в sRGB-байтах затемняет полупрозрачные края.
- Атлас покрытия — `Rgba8Unorm` с байтами `[c, c, c, c]` без `premultiply`: это уже линейный премультиплицированный белый. Через sRGB-формат покрытие 128 даёт RGB ≈ 0,216 при α ≈ 0,502, повторная премультипликация — тоже затемняет; оба дают тёмную кайму у глифов.
- Кэш шрифта по пути без `px` отдаёт атлас и метрики другого размера.
- Каждый глиф в атласе окружён пустой рамкой в 1 texel, и у края атласа тоже: без неё `Linear` подмешивает соседний глиф в кайму.
- `tint.a` умножает в шейдере и RGB: текстура премультиплицирована, а `Sprite::color` — нет. Без этого полупрозрачный tint при `PREMULTIPLIED_ALPHA_BLENDING` осветляет кадр вместо прозрачности.
- `step_frame` очищает `gfx.sprites` прямо перед `draw`, а не после рендера: на кадре без рендера (свёрнутое окно, потерянная поверхность) спрайты копились бы и рисовались дважды.
- Порядок между разными текстурами внутри одного слоя не гарантирован: батчер сортирует по `(слой, текстура)`. Перекрывающиеся спрайты разных текстур — только в разных слоях.
- Пиксельный вьюпорт: дробный масштаб или дробный отступ растягивает часть мировых пикселей на лишний экранный, `Nearest` сэмплит соседнюю ячейку атласа — швы между тайлами. Округлённая камера без округлённых спрайтов даёт дрожание спрайтов относительно тайлов.
- Глубина в wgpu — `0..1`, не `-1..1` как в OpenGL: ортоматрица — `glam::camera::rh::proj::directx::orthographic` (Z `0..1`, Y вверх), с `near = -1, far = 1` она кладёт `z = 0` в 0.5. Матрица из `opengl` отсекла бы половину сцены без ошибки, из `vulkan` — перевернула бы Y.
- Поверхность не падает, а восстанавливается: `Outdated` — `configure`, `Lost` — пересоздать `Surface`, окно с нулевой стороной — не рисовать.
- Потеря фокуса сбрасывает зажатые клавиши, иначе отпущенная в другом окне клавиша «залипает».
- Цикл событий в `Wait`, следующий кадр запрашивается из `RedrawRequested`. `Poll` на Wayland с vsync крутит ядро на 100% между кадрами композитора. Linux не сообщает о сворачивании (X11 даёт только `Occluded`), поэтому свёрнутое окно без vsync на Wayland продолжает рисовать.
- FPS за окно не говорит о нагрузке кадра: `FrameStats` берёт интервал между концами успешных `render` и число спрайтов того же кадра. Отметка по началу кадра отвязывает длительность от спрайтов, а пауза в рендере (кадр без рендера или интервал длиннее 250 мс — свёрнутое окно на Wayland `Ok(false)` не даёт) без сброса окна попадёт в `worst` секундами и занизит fps.
- `Solid` собирает пассажиров до движения по обеим осям: после сдвига по X пассажир может оказаться не над платформой и потерять riding по Y.
- Двигающийся `Solid` исключён из препятствий своих толкаемых и пассажиров, иначе он блокирует собственный push и давит каждого.
- Заблокированный carry — не смерть: `squished` только при неудачном push, иначе платформа у стены убивает стоящего на ней.
- Push и carry — `move_exact` без остатка Actor: через остаток сдвиг округлился бы в лишний пиксель и пассажир съезжал бы с платформы.
- Заметённые AABB двух движущихся тел пересекаются ложно: тела касаются одного места в разное время тика. Поэтому контакт — сенсор на пиксельном шаге.
- Сенсор ловит вход только движущегося тела: враг, вошедший в стоящего игрока, виден лишь проверкой пересечений в конце тика.
- Клетка тайловой карты — `div_euclid`, не `/`: деление округляет к нулю, и `−1 / 18 = 0` кладёт отрицательную координату в клетку 0.
- Туннелирование быстрых тел: ограничение скорости и подшаги, CCD позже.
- Коллизия с движущимся телом — заметанием отрезка относительного движения против AABB, расширенного на полуразмер. Проверка только конечных положений пропускает касание угла: в Pong ракетка за тик сдвигается вниз, мяч вправо, и в обоих концах тика они не пересекаются.
- Телепорт (подача из центра) ставит `prev = cur`, иначе интерполяция нарисует пролёт через всё поле.
- Перенос через край мира сдвигает `prev` на тот же вектор, что и `pos`: иначе кадр между тиками нарисует пролёт через всё поле.
- Угол для интерполяции не нормализуется: lerp от 6,27 к 0,05 после приведения к `[0, 2π)` крутит спрайт почти полный оборот назад.
- В звуковом колбэке нет аллокаций, блокировок и ввода-вывода. Иначе будет треск.
- Частота файла ≠ частоте устройства: ресемплинг при загрузке, иначе меняется высота звука.

## Этапы

| Этап | Движок | Игра | Готово, когда |
|---|---|---|---|
| 0 | окно, фиксированный шаг, ввод, трейт `Game` | цвет фона по клавише | 60 тиков/с при любом FPS, нажатие ловится ровно один раз |
| 1 | `wgpu`, текстуры, батчер, ортокамера | Pong | играбельно, ресайз не ломает |
| 2 | ECS, хэндлы, буфер команд, текст | Asteroids | 5 000+ спрайтов при 60 FPS |
| 3 | коллизии, кинематика, триггеры, микшер | платформер | не застревает и не проваливается, звук без треска |
| 4+ | динамика, `egui`-редактор, горячая перезагрузка, 3D | по ситуации | — |

Чистая логика (ECS, коллизии, микшер) покрывается юнит-тестами, рендер и звук проверяются играми и отладочным оверлеем. Достаточность тестов меряют покрытие строк с порогом (`make cov`, только вверх; `app.rs` и `renderer.rs` — склейка, вне замера; чистая логика поверхности вынесена в `surface.rs` и меряется) и мутанты (`make mutants`, выживших нет вне исключений с причиной).
