# Дизайн движка

## Цель

Универсальный движок: сначала 2D, потом 3D. Каждая функция движка появляется только тогда, когда она нужна конкретной игре из `games/`. Без игры-потребителя архитектура растёт вслепую.

## Решения

| Решение | Почему |
|---|---|
| Rust | безопасная память, cargo, `wgpu` |
| Готовое: `winit`, `wgpu`, `glam`, `image`, `cpal`, `hound`, `lewton`, `rtrb`, `fontdue`, `egui`, `gltf`, `serde`, `toml` | платформа, форматы и виджеты инструментов — не движок; месяцы на драйверы и парсеры ничему не учат |
| Своё: цикл, рендер, ECS, ресурсы, физика, микшер | это и есть движок |
| ECS и хэндлы вместо ссылок между объектами | граф объектов со ссылками упирается в borrow checker |
| Рендер на GPU с камерой-матрицей с первого дня | 3D добавляется перспективой, мешами и глубиной без переписывания |
| MIT, крейт `stapel`, публичный слой (README, крейт) по-английски | движок для чужих игр через агентов; `engine` на crates.io занято, переименование после первой чужой игры сломало бы её `use` |

## Структура

Cargo workspace: `engine/` (библиотека, крейт `stapel`), `games/<имя>/` (бинарники). Движок не знает об играх.

Слои снизу вверх: платформа → цикл и время → рендер → ресурсы → мир (ECS) → физика → звук.

## Цикл

- `winit` владеет циклом событий, поэтому движок — фреймворк, а игра реализует трейт `Game { init, update, draw(alpha), ui }`; `ui` — панели egui раз в кадр, по умолчанию пусто.
- Симуляция — фиксированный шаг 60 Гц, отрисовка — свободная, с интерполяцией по `alpha`. `dt` за кадр ограничен 250 мс.
- Кадр до рендера — `step_visual`: `begin_pass`, `step_frame`, `CursorGrab::sync`, `Game::ui`, `Audio::flush`, снятие фокуса egui, `end_pass`, `tessellate`. Окно и (дальше) runner различаются источником `RawInput`, `dt` и адаптером захвата (`WindowGrab`, `VirtualGrab`). → тест `frame::visual_frame_keeps_order`
- Порядок тика: ввод → логика → физика → события коллизий → отложенное удаление сущностей.

## Рендер

- Immediate-mode API `draw_sprite(...)`: вызовы копятся на CPU, сортируются по `(слой, текстура)` и рисуются через instancing. Новый draw call — только при смене текстуры.
- Рендер не знает об ECS: система спрайтов кормит тот же батчер.
- `Gfx::draw_sprite(Sprite { texture, pos, size, rotation, uv, color, layer })` — прямоугольник с центром в `pos`, повёрнутый на `rotation` против часовой, с UV-подпрямоугольником `uv` (доли текстуры, `(0, 0)` — левый верхний). Литералы — через `..Default::default()`: белый tint, вся текстура `WHITE`. `cos/sin` считаются на CPU, в шейдере поворот геометрии отдельно от UV.
- Мир фиксированного размера (`Camera2D { center, size }`, Y вверх) вписывается в окно с полями (`letterbox`): поле игры не зависит от пропорций окна. Поля — цвет `clear_color`, `set_viewport` ограничивает только геометрию.
- Пиксель-арт (`Config::pixel_perfect`) — `letterbox_pixel`: масштаб `floor(min(W/w, H/h))`, отступы — целая половина остатка; окно меньше мира — дробный `letterbox`. Камера и края всех спрайтов — на целых мировых пикселях: позиция `round(lerp(prev, cur, alpha))` с одним `alpha` на кадр, центр спрайта нечётного размера — на `.5`. Тогда швов атласа нет без экструзии тайлов.
- Кадр рисуется в промежуточную `Canvas` (`Rgba8UnormSrgb`), `PresentPass` копирует её на поверхность: окно и runner делят один путь рисования. Цена замера (`NO_VSYNC=1`, release, без ввода, медиана; до → после): racing (гараж) 1589 → 1538 fps (+0,021 мс на кадр), shooter (старт) 1679 → 1454 fps (+0,092 мс на кадр, падение 13,4%); адаптер тот же, AMD Radeon Graphics (RADV RENOIR), Vulkan.

## Runner

- `Runner<G>` (`engine/src/runner.rs`) проигрывает `Script` без окна: по одному виртуальному кадру на тик через `step_visual`, `VirtualGrab` и `FrameRenderer` в `Canvas`. `run_script` — офскрин-обёртка: `Gpu::headless`, снимки по `script.snapshots`, PNG в `out`.
- Тик 0 — начальный кадр с `dt = 0`: `update` не вызывается, но есть `draw`, `ui`, рендер и `shown`, без которых нет геометрии панелей для `wants_pointer`. Тик N ≥ 1: события тика по порядку файла, затем кадр с ровно одним `update`. Снимок N — после рендера кадра N.
- Часы — `FixedClock::new(tick_hz, Duration::MAX)` и `dt = clock.step()`: один `update` на кадр при любой частоте.
- Начальное состояние: фокус есть (в `Context` и `RawInput` одинаково), курсора нет, захвата нет. Захват, запрошенный в `update` тика N, виден с N+1.
- Для события порядок как в окне: событие в очередь egui, `wants_pointer` по прошлому проходу и курсору до события, затем `Input`. Координаты `Input` физические, в egui делятся на `scale` один раз.
- Клавиши egui берутся по имени `KeyCode` (`KeyA` → `A`, `Digit1` → `Num1`); модификаторов и `Text` нет, ввод текста в панели сценарием не проверить.
- `Game::report` — JSON-объект; иное — `RunError::Report` с тиком. `texts` в отчёте — строки, отправленные в `draw_text`, а не видимые.

- `--window` — тот же `Runner`: `ScriptApp` (`app.rs`) на каждом `RedrawRequested` делает `Runner::advance`, `Renderer::present_canvas` выводит `Canvas` сценария на поверхность своего размера. События окна, кроме закрытия и resize, игнорируются; закрытие до последнего тика — `RunError::Closed`. `Gpu` создаёт `Renderer` под поверхность, `Runner` берёт его.
- Цепочка кадров рвётся, пока композитор не даёт кадров (в окне на скрытом столе Wayland); прогон тогда стоит, артефакты не пишутся дальше. Проверено на X11 (`WAYLAND_DISPLAY` снят).

## 3D

- Проходы кадра: 3D-мир (`Clear` цветом `clear_color` и глубины, на всю поверхность, aspect поверхности) → слой оружия `Scene::viewmodel` (цвет `Load`, глубина `Clear`) → спрайты с `Load` поверх (HUD — `Camera2D` с letterbox) → egui. Без `gfx.scene` спрайты сами чистят кадр — 2D-игры не меняются.
- `gfx.scene: Option<Scene>` — immediate-mode, как спрайты: игра заполняет в `draw`, `step_frame` ставит `None` перед `draw`.
- Слой оружия — `Viewmodel { fov_y, near, models }`: свои у слоя только угол обзора и ближняя плоскость, позиция, взгляд, свет и туман — сцены. Так свет ложится на оружие верно, а рассинхрон позиции слоя и мира невыразим. Чистая глубина — ствол не уходит в стену. У прохода свои uniform, инстансы и палитры (`PassBuffers`, у `MeshPipeline` их два), меши и пайплайны общие; `MeshPipeline::draw_scene` рисует оба прохода.
- Ортография — флаг `Camera3D::ortho: Option<f32>` (видимая высота кадра в мире, ширина — `height · aspect`, глубина та же: `near` → 0, `far` → 1), а не `enum Projection`: `fov_y` ортокамере не нужен, но три игры читают его напрямую. Луч курсора строится через обратную `view_proj` и для ортографии годится без правок: лучи параллельны, начала разнесены. Слой оружия явно ставит `ortho: None`.
- Меш — `Assets::add_mesh(vertices, indices)` → `Handle<Mesh>`, заливка через pending, как текстуры; индексы u32. Позиции и индексы остаются на CPU в `Assets::mesh_geometry` — для мира столкновений; копия одна на меш, повторная загрузка модели её не дублирует. `MeshDraw { mesh, texture, color, transform }` раскрывается на CPU в инстанс (матрица, нормальная матрица и `tint` — линейный множитель текстуры), батчи — по `(mesh, texture)`: цвет в ключ не входит, порядок между батчами решает глубина.
- Модель — `Assets::load_model(path)` → `Handle<Model>`: GLB с буфером внутри, узлы с локальным TRS, скины (суставы в порядке `skin.joints`, IBM), анимации только `LINEAR` с каналами T/R/S. Меши заливаются через `add_mesh` (индексы расширяются до u32), базовая текстура — `load_texture` по URI относительно файла, так что делит хэндл и горячую перезагрузку с остальными текстурами. Материал — имя и `baseColorFactor` как есть (линейный по спецификации glTF) в `Model::materials`, `Primitive::material` — индекс; примитиву без материала достаётся белый без имени в конце списка. Цвет материала уходит `color` в `MeshDraw`/`SkinnedDraw` и умножает текстуру: у Racing Kit текстур нет, цвет только в материале. Сам файл модели горячо не перезагружается: замена узлов и мешей под живыми позами игры — сложность без нужды этапа. Ошибка разбора — пустая модель и `warn`; разбор целиком идёт до заливки, полмодели в `Assets` не остаётся. `KHR_materials_unlit` принимается и не учитывается: Blocky Characters требуют его в `extensionsRequired`, а персонажам в освещённом лесу нужен свет, как остальным.
- Поза — CPU: `Model::pose(anim, t, looped, &mut Pose)` сэмплирует каналы (T/S — lerp, R — slerp по короткой дуге, за краями — крайний ключ), собирает глобальные матрицы узлов (родитель раньше детей при любом порядке в файле; цикл в иерархии — ошибка загрузки) и палитры скинов `G_joint × IBM`. Поза покоя `Model::rest` считается при загрузке. `ModelDraw { model, transform, pose }` раскрывается в `ExpandedModels`: жёсткий меш — `MeshDraw` с `transform × G_mesh` в общие батчи, меш со скином — `SkinnedDraw` с `transform` и своей палитрой на пару «экземпляр — скин». Ручная поза — `Pose::local_mut(node)` правит локальный TRS, `Model::recompose` пересобирает глобальные матрицы и палитры.
- Скиннинг — на GPU: `vs_skinned` смешивает до 4 матриц палитры по весам вершины, поверх — `transform` инстанса. Палитры кадра лежат в одном uniform-буфере с шагом `MAX_JOINTS × 64 = 4096` Б и выбираются динамическим смещением; меш со скином — вызов на инстанс. Скин длиннее `MAX_JOINTS = 64` не рисуется, `warn` один раз за жизнь конвейера.
- Прозрачность моделей — дизеринг, без сортировки и смешивания: `ModelDraw::tint` умножает цвет материалов, фрагмент с итоговой `a` не выше порога Байера 4×4 отбрасывается, оставшиеся пишут глубину и цвет с `a = 1`. Сетка видна; альфа-проход с сортировкой — без нужды этапа: полупрозрачны только призрак и превью редактора.
- Отсечения граней нет: Mini Dungeon и Car Kit помечены `doubleSided`, Racing Kit — нет, но его обмотка согласована с нормалями и без отсечения рисуется так же. Отсечение по материалу — второй пайплайн без нужды этапа.
- Обзор мышью — сырой `DeviceEvent::MouseMotion` в `Input::mouse_delta`, копится до `end_tick`: `CursorMoved` при захвате стоит на месте. Игра просит захват `ctx.cursor_grab`, app после тиков кадра пробует `Locked`, затем `Confined`, прячет курсор и ставит `ctx.grabbed`; отказ обеих — `cursor_grab = false` и `warn` один раз. Сдвиг принимается только при фокусе и `grabbed`.
- Свет по фрагменту: `ambient` + `Scene::sun` (`DirectionalLight`, Ламберт без затухания и теней; `dir` — куда идут лучи, нормируется на CPU, нулевой гасит) + до `MAX_LIGHTS = 16` `PointLight` — Ламберт × затухание `max(1 - d/range, 0)²`; затем туман `clamp((d - start)/(end - start), 0, 1)` по расстоянию от камеры к `fog.color`. Лишние источники отбрасываются с одним `warn` за жизнь конвейера; `Fog::default()` — без тумана.

## ECS

- Сущность = индекс + поколение.
- Хранение — sparse set; архетипы, только если профайлер покажет, что запросы — узкое место.
- Хранилища в `RefCell`: конфликт `&mut` даёт панику, а не UB.
- `World`, компоненты и системы принадлежат игре: `World` в структуре игры, не в `Context`. `Transform` в движок не переезжает: тела платформера (целые AABB) и Asteroids (f32 с углом) разные.
- Системы — методы игры по порядку тика, обход одного хранилища + `get` в другом. Параллельный планировщик, запросы на трейтах кортежей и иерархия — когда понадобятся.

## Ресурсы, физика, звук

- `Handle<T>` — индекс, кэш «путь → хэндл». Отсутствующий файл заменяется заглушкой и пишется в лог; заглушка тоже кэшируется по пути.
- Поколения в хэндле нет, пока нет выгрузки: индексы append-only на всём сроке `Assets` и GPU-таблицы. Первое переиспользование слота обязано ввести поколение, иначе старый хэндл молча рисует чужой ресурс. Перезагрузка файла — не переиспользование: хэндл по-прежнему значит тот же путь, поколение не нужно.
- Горячая перезагрузка: `Assets` помнит `Stamp { mtime, len }` каждого файла, app раз в 0,5 с зовёт `reload_changed`. Изменённая текстура встаёт в pending под прежним хэндлом, `upload` заменяет её bind group. Ошибка декода — прежний ресурс и один `warn` на версию файла. Правка с тем же `Stamp` не заметна — принято для дев-инструмента. Файлы игры (уровень, трасса) — `stapel::Watcher`: игра зовёт `tick` в `update`, раз в `WATCH_TICKS` файл перечитывается и сравнивается по содержимому с базой.
- Шрифт: `load_font(path, px)` растеризует ASCII 32..=126 через `fontdue` в атлас покрытия, кэш по `(path, px)`. Ошибка — `warn` и заглушка без атласа: глифы — белые прямоугольники.
- Физика — целочисленная модель Celeste: свободные функции над `Tilemap` и срезами тел игры, о `World` не знает. `Actor` движется шагами по 1 px (X, потом Y) с дробным остатком — без туннелирования и застревания, пока старт свободен. `Solid` проходит сквозь тайлы, толкает пересечённых и везёт стоящих сверху `Actor`.
- Триггеры — сенсоры, проверяемые на каждом пиксельном шаге: известны ось и направление входа. Заметённые AABB не используются.
- Отложены: круг, сетка для динамических тел (их десятки — перебор), слои и маски, события enter/exit, динамические тела.
- Звук: колбэк `cpal` в потоке реального времени, команды через lock-free очередь `rtrb`, звуки и музыка декодируются в память целиком. Длящиеся голоса (`start_loop`, `set_loop`, `stop_loop`) — отдельный пул из `LOOPS` слотов. Отложена кража голосов.
- Эффект в пространстве — `play_stereo(sound, Stereo::at(camera, pos, volume, range))`: панорама равной мощности по `yaw` (наклон головы её не меняет), затухание `max(1 − d/range, 0)²`, как у света. Файл сводится в моно по флагу команды. Длящиеся голоса панорамы не имеют. Отложены HRTF и доплер.

## Физика 3D

- Граница: в движке (`stapel::physics3d`) — тело, геометрические запросы к статическому миру и контактный отклик; подвеска, шины, привод и правила гонки — геймплей и характеристики машины, живут в игре.
- `RigidBody`: центр масс `pos`, `rot` тело → мир, `vel` и `ang_vel` в мире, `inv_mass`, диагональ `inv_inertia` в осях тела (`box_inertia` — брусок). Сила и момент копятся `apply_force_at` до шага, импульс `apply_impulse_at` меняет скорости сразу.
- Шаг разделён: `integrate_velocity(dt, gravity)` (тяжесть, накопленное, гироскопический член, демпфирование `exp(−λ·dt)`) → контакты правят скорость → `integrate_position(dt)` (позиция, кватернион `q += ½·ω·q·dt` с нормировкой). Так отклик видит скорость следующего сдвига.
- Гироскопический член — неявный шаг Catto (одна итерация Ньютона в осях тела): явный `ω×(Iω)` за 10 с кувырка накачал |L| на 3 %. Неявный гасит: |L| до 3 %, энергия до 7 % за 10 с — приемлемо при угловом демпфировании машины.
- `StaticWorld`: треугольники в мире с `tag` игры, сетка по XZ (каждый треугольник — во всех ячейках своего AABB). `raycast` берёт ячейки AABB отрезка, кандидатов сортирует и дедуплицирует, проверяет обе стороны с рёбрами включительно — луч точно в шов не проваливается. Ближайшее среди прошедших фильтр, при равных `t` — меньший индекс: результат не зависит от порядка ячеек.
- `sphere_contacts` дописывает контакты сферы `{ point, normal, depth, tri, tag }`; контакт односторонний: центр за плоскостью треугольника пропускается. При построении вершины склеиваются в пределах ~1 мм. Ребро, которое делят ровно два треугольника с углом нормалей до ~8°, — внутреннее; вершина внутренняя, если внутренние все её рёбра. Ближайшая точка на внутреннем ребре или вершине даёт нормаль грани и глубину до её плоскости, на внешних — направление к центру.
- `solve_contacts(body, contacts, params)` — отклик одного тела на контакты с миром: последовательные импульсы по общему набору `iterations` раз, эффективная масса с вращением, Кулон кругом `|jt| ≤ μ·jn` по накопленному импульсу (трение раньше нормали в проходе). Упругость — только при сближении быстрее `restitution_threshold`. Глубину исправляет прямой сдвиг `pos` проекциями на полупространства контактов, оставляя `slop`, не дальше `max_correction`; скорость он не трогает. Контакты ближе 1 см с нормалями почти параллельными сливаются в самый глубокий (шов даёт два одинаковых), остальные сортируются по точке.

## Молчаливые поломки

После «→» — что ловит нарушение: тест (`модуль::имя`), API, запуск, ревью, будущее (с триггером); **пробел** — защиты нет, хотя тест возможен.

### Ввод и цикл

- Флаги ввода «только что» сбрасываются после первого тика кадра, а не после кадра: за кадр бывает 0 или 2 тика. → тест `frame::press_is_seen_only_by_first_tick`
- `step_frame` очищает `gfx.sprites` прямо перед `draw`, а не после рендера: на кадре без рендера (свёрнутое окно, потерянная поверхность) спрайты копились бы и рисовались дважды. → тест `frame::previous_sprites_vanish_even_without_ticks`
- Курсор переводится в мир по камере и вьюпорту последнего показанного кадра (`Context::shown`), не по `gfx.camera`: камеру игра двигает в `update` до того, как кадр с ней показан, и клик попал бы не в ту клетку, что под курсором на экране. app ставит `shown` только после показа и сбрасывает в `None` на resize — иначе старый вьюпорт. → тест `frame::cursor_world_uses_shown_camera_not_gfx`; порядок в `app.rs` — ревью
- Луч из курсора (`Context::cursor_ray`) строится по 3D-камере показанного кадра (`Shown::scene`) и полной поверхности, не по вьюпорту спрайтов: 3D рисуется на всю поверхность, и при летербоксе луч по вьюпорту уходил бы мимо того, что под курсором. → тесты `frame::cursor_ray_uses_shown_camera_and_full_surface`, `camera::ray_points_project_back_to_their_ndc`
- egui получает все события окна, `Input` — все, кроме нажатия кнопки мыши над панелью по текущему курсору: `egui_wants_pointer_input` берёт позицию прошлого прохода, и клик сразу после захода на панель ушёл бы и в мир. Отпускание идёт в `Input` всегда: нажатая в мире кнопка, отпущенная над панелью, иначе осталась бы `down`. → тесты `ui::release_always_reaches_input`, `ui::wants_pointer_uses_current_cursor`
- Колесо над панелью по текущему курсору идёт только в egui: прокрутка списка панели иначе зумила бы и мир под ней. → тест `ui::wheel_over_ui_does_not_reach_input`

- Потеря фокуса сбрасывает зажатые клавиши, иначе отпущенная в другом окне клавиша «залипает». → тест `input::focus_lost_clears_held_keys`; вызов из `app.rs` — запуск
- Сдвиг мыши без фокуса или захвата — движение курсора по чужим окнам и панелям: обзор крутился бы, пока игрок работает в другом окне. Потеря фокуса снимает `cursor_grab`, `grabbed` и сдвиг. → тесты `frame::mouse_motion_counts_only_when_focused_and_grabbed`, `frame::focus_lost_releases_grab_and_input`
- `Locked` на X11 нет (`NotSupported`) — нужен откат на `Confined`; захват на Wayland не снимается сам при потере фокуса — app снимает его явно, иначе курсор заперт в чужом окне. → запуск на X11 и Wayland
- Сдвиг мыши потребляет первый тик кадра, `draw` добавляет к углу ещё не потреблённый и состояния не меняет: прибавка в `draw` к состоянию учла бы сдвиг дважды, без неё на кадрах без тиков обзор дёргается. → тест `maze::mouse_turns_once_in_update_and_draw_adds_unconsumed`
- Захват — только по клику при `ctx.focused`: клик, пришедший до потери фокуса и разобранный после, захватил бы курсор в фоновом окне. → тесты `maze::click_before_focus_loss_does_not_grab`, `maze::click_grabs_cursor_only_when_focused`
- Цикл событий в `Wait`, следующий кадр запрашивается из `RedrawRequested`. `Poll` на Wayland с vsync крутит ядро на 100% между кадрами композитора. Linux не сообщает о сворачивании (X11 даёт только `Occluded`), поэтому свёрнутое окно без vsync на Wayland продолжает рисовать. → запуск: загрузка CPU на Wayland
- FPS за окно не говорит о нагрузке кадра: `FrameStats` берёт интервал между концами успешных `render` и число спрайтов того же кадра. Отметка по началу кадра отвязывает длительность от спрайтов, а пауза в рендере (кадр без рендера или интервал длиннее 250 мс — свёрнутое окно на Wayland `Ok(None)` не даёт) без сброса окна попадёт в `worst` секундами и занизит fps. → тест `stats::long_interval_is_pause_without_reset`; отметка и сброс в `app.rs` — запуск

### Рендер

- sRGB: текстуры цвета и поверхность — `*Srgb`, данные — линейные. Иначе цвета искажаются без ошибки. → тест `surface::picks_only_srgb_format`, `sprite_pipeline::offscreen_render`
- Premultiplied alpha, иначе на краях спрайтов тёмная кайма. → тест `assets::loads_png_premultiplied`
- Премультипликация — в линейном пространстве: sRGB → linear → ×α → sRGB, α без гаммы (белый при α = 128 хранится как 188). Умножение прямо в sRGB-байтах затемняет полупрозрачные края. → тест `assets::premultiply_is_linear`
- Атлас покрытия — `Rgba8Unorm` с байтами `[c, c, c, c]` без `premultiply`: это уже линейный премультиплицированный белый. Через sRGB-формат покрытие 128 даёт RGB ≈ 0,216 при α ≈ 0,502, повторная премультипликация — тоже затемняет; оба дают тёмную кайму у глифов. → тест `assets::coverage_is_not_premultiplied`; формат — `offscreen_render`
- Кэш шрифта по пути без `px` отдаёт атлас и метрики другого размера. → тест `assets::font_is_cached_by_path_and_px`
- Каждый глиф в атласе окружён пустой рамкой в 1 texel, и у края атласа тоже: без неё `Linear` подмешивает соседний глиф в кайму. → тест `text::packed_glyphs_keep_padding`, `sprite_pipeline::glyph_padding_keeps_neighbour_out`
- `tint.a` умножает в шейдере и RGB: текстура премультиплицирована, а `Sprite::color` — нет. Без этого полупрозрачный tint при `PREMULTIPLIED_ALPHA_BLENDING` осветляет кадр вместо прозрачности. → тест `offscreen_render`
- Порядок между разными текстурами внутри одного слоя не гарантирован: батчер сортирует по `(слой, текстура)`. Перекрывающиеся спрайты разных текстур — только в разных слоях. → запуск: соблюдение играми не проверяется; сортировку держит `sprite::sorts_by_texture_within_layer`
- Пиксельный вьюпорт: дробный масштаб или дробный отступ растягивает часть мировых пикселей на лишний экранный, `Nearest` сэмплит соседнюю ячейку атласа — швы между тайлами. Округлённая камера без округлённых спрайтов даёт дрожание спрайтов относительно тайлов. → тест `camera::pixel_scale_is_floored_and_centered`, `platformer::sprite_interpolates_to_whole_pixels`; швы на экране — запуск
- Глубина в wgpu — `0..1`, не `-1..1` как в OpenGL: ортоматрица — `glam::camera::rh::proj::directx::orthographic` (Z `0..1`, Y вверх), с `near = -1, far = 1` она кладёт `z = 0` в 0.5. Матрица из `opengl` отсекла бы половину сцены без ошибки, из `vulkan` — перевернула бы Y. → тест `camera::z_zero_is_mid_depth`, `camera::y_points_up`
- Перспектива — `directx::perspective` (глубина `0..1`): вариант `opengl` (`-1..1`) молча срезал бы ближнюю половину глубины. → тест `camera::near_is_depth_zero_far_is_one`
- egui смешивает в гамме: рисует в линейный вид `Canvas` (`view_formats`, нужен `VIEW_FORMATS`), иначе полутона панели искажены и egui пишет warn на старте; без флага рисует в основной вид. → запуск: warn в логе
- Вывод `Canvas` на поверхность — пара видов, линейная только при `VIEW_FORMATS` и `SURFACE_VIEW_FORMATS` (в wgpu — только Vulkan) одновременно, иначе обе стороны `*Srgb`: линейный источник при цели `*Srgb` кодируется второй раз, картинка светлая. Второй вид поверхности без флага валит `configure`. → тест `present::linear_only_with_both_flags`, `present::srgb_target_keeps_halftones_for_canvas_with_linear_view`
- `PresentPass` читает `textureLoad` 1:1 от левого верхнего угла с зажимом в размер `Canvas`: цель больше источника иначе читала бы за границей, а после `resize` `Canvas` и поверхность должны пересоздаваться вместе. → тест `present::resize_keeps_one_to_one_and_clamps_larger_target`
- egui собран без `default_fonts`: игра с `Game::ui` без `stapel::ui::set_font` получит панель без шрифта. → запуск
- `textures_delta.set` применяется до проверки поверхности, как `textures.upload`: атлас шрифта egui присылает один раз, и на пропущенном кадре он пропал бы навсегда. `free` — после submit или сразу на пропущенном кадре. → ревью
- egui-pass — с `LoadOp::Load`: `Clear` стёр бы кадр игры под панелью. → запуск
- Замена текстуры идёт через тот же pending, что и создание: одна пачка может нести `[0, 1, 1]` — слот 1 создаётся и тут же заменяется. `upload` без ветки замены упал бы на ассерте порядка, а без строгого FIFO в `take_pending` замена ушла бы раньше создания. → тест `gpu_textures::reloaded_texture_replaces_its_slot`
- Версия файла запоминается и при ошибке декода, иначе битый файл перечитывается и пишет `warn` каждые 0,5 с. → тест `assets::broken_reload_keeps_old_texture_and_remembers_version`
- Поверхность не падает, а восстанавливается: `Outdated` — `configure`, `Lost` — пересоздать `Surface`, окно с нулевой стороной — не рисовать. → тест `surface::status_to_action`; исполнение в `Renderer::render` — запуск

### 3D

- `step_frame` ставит `gfx.scene = None` перед `draw`, как чистит спрайты: игра без `scene` в этом кадре показала бы старый 3D-кадр. → тест `frame::previous_scene_vanishes_even_without_ticks`
- Нормали — через обратную транспонированную к `transform` без переноса, не через саму матрицу: при неравномерном масштабе нормаль иначе перестаёт быть перпендикулярной грани и свет ложится не туда. → тест `scene::normal_matrix_is_inverse_transpose`
- Sprite pass при `gfx.scene` — с `LoadOp::Load`: `Clear` стёр бы 3D под HUD. → тест `mesh_pipeline::unlit_color_is_ambient_texture_tint_and_sprites_stay_on_top`; выбор режима в `renderer.rs` — ревью
- Затухание — `max(1 - d/range, 0)²`: без `max` за `range` основание отрицательное, квадрат снова растёт, и дальние стены светятся. → офскрин `mesh_pipeline::point_light_lambert_and_falloff`
- WGSL выравнивает `vec3` в uniform до 16 байт, массив структур — до 16: Rust-структура без этого сдвигает поля, и шейдер читает свет и туман со смещением. → тест `mesh_pipeline::uniform_layout_matches_wgsl` сверяет смещения с разбором `mesh.wgsl` naga
- Меш со скином не берёт матрицу своего узла `G_mesh`: позу задают суставы, а `G_mesh` сдвинул бы меш второй раз (glTF требует её игнорировать). → тест `scene::skinned_mesh_ignores_its_node_transform`
- Палитра идёт в порядке `skin.joints`, не узлов модели: `Vertex::joints` индексирует суставы скина, другой порядок крутит руку вместо ноги. → тест `model::palette_is_joint_global_times_ibm_in_skin_joints_order`
- `baseColorFactor` берётся как есть: по спецификации он линейный, и пропущенный через sRGB → linear асфальт 0,267 стал бы 0,058 — почти чёрным без ошибки. → тест `model::road_materials_keep_linear_base_color`
- Жёсткий меш с позой берёт `G_mesh` из `pose.globals`, не из покоя: иначе ворота не поднимаются. → тест `scene::rigid_mesh_takes_node_from_pose_or_rest`
- Габариты `Node::bounds` — в пространстве узла, `Model::bounds` умножает их на `G_node` позы покоя: у деталей Racing Kit корень сдвинут на (−0,35; −0,01; −0,65), и габариты меша без `G_node` сместили бы деталь на 0,35 клетки. → тест `model::road_bounds_include_unity_root`
- Глобальные матрицы считаются в порядке «родитель раньше ребёнка»: в порядке файла ребёнок перед родителем умножился бы на его локальную матрицу вместо глобальной. → тест `model::child_global_is_parent_times_local_in_any_file_order`
- Инстансы мешей со скином лежат в буфере после жёстких, вызов на инстанс берёт индекс со смещением `first_skinned`: без него орк рисуется с матрицей стены. → офскрин `mesh_pipeline::skinned_instances_follow_rigid_ones`
- Нормаль меша со скином поворачивается той же матрицей скина, что и позиция: иначе свет на анимированном орке ложится по позе покоя. → офскрин `mesh_pipeline::skinned_normal_turns_with_joint`
- Палитры — uniform, не storage: storage-буфера в вершинном шейдере на GL может не быть, и скиннинг упал бы на создании пайплайна только там. → ревью
- Шаг палитр кратен `min_uniform_buffer_offset_alignment`: иначе динамическое смещение не проходит валидацию. → `assert` в `MeshPipeline::new`, тест `mesh_pipeline::palette_stride_is_multiple_of_device_alignment`
- Дизеринг включается при любой итоговой `a < 1` — от `tint`, `MeshDraw.color` и альфы текстуры: 3D-текстура или материал с альфой молча станут решетчатыми. Отброшенный фрагмент глубину не пишет, иначе за призраком пропал бы мир. → офскрин `mesh_pipeline::translucent_is_dithered_without_depth`
- Буферы проходов мира и слоя раздельные: `write_buffer` идёт до `submit`, и слой в общие буферы перезаписал бы инстансы, камеру и палитры мира — стены рисовались бы на месте оружия, а скиннинговые модели мира в позе моделей слоя. → офскрин `mesh_pipeline::pixels_outside_viewmodel_match_frame_without_it`, `mesh_pipeline::viewmodel_skin_leaves_world_skin_palette`
- Камера слоя оружия собирается из камеры сцены через `..` и явно ставит `ortho: None`: иначе слой унаследует ортографию сцены, и его `fov_y` молча перестанет действовать. → офскрин `mesh_pipeline::pixels_outside_viewmodel_match_frame_without_it` (случай ортосцены)
- Туман считается от `camera.pos`, а у ортокамеры это точка отвода вдоль взгляда (`CAMERA_BACK` в `trains`): туман с ортографией молча зависел бы от отвода, а не от кадра. `trains` тумана не ставит. → будущее: туман в ортоигре — мерить по оси взгляда
- Расширение из `extensionsRequired` без фичи крейта `gltf` — ошибка разбора: модель молча пуста, в логе только `warn`. Так пропадали персонажи Blocky. → тесты `model::required_unlit_material_parses_and_stays_lit`, `shooter::every_model_loads_and_characters_have_clips`
- Буфер глубины пересоздаётся в `resize` вместе с поверхностью: иначе проход падает на валидации размеров вложений. → запуск: ресайз окна с 3D

### Физика

- `Solid` собирает пассажиров один раз, до движения по обеим осям, — выбор. Пересчёт перед каждой осью отличается только у диагональной платформы: при заблокированном carry по X пассажир, уже не стоящий на ней, всё равно едет по Y, а вставший после сдвига по X — не едет. Платформы платформера одноосные, разница не наблюдаема; тест сейчас закрепил бы произвольный выбор. → будущее: диагональные платформы
- Двигающийся `Solid` исключён из препятствий своих толкаемых и пассажиров, иначе он блокирует собственный push и давит каждого. → тест `solid::other_solid_blocks_push_but_mover_does_not`
- Заблокированный carry — не смерть: `squished` только при неудачном push, иначе платформа у стены убивает стоящего на ней. → тест `solid::carry_into_wall_stops_rider_without_squish`
- Push и carry — `move_exact` без остатка Actor: через остаток сдвиг округлился бы в лишний пиксель и пассажир съезжал бы с платформы. → тесты `solid::rider_travels_along_x_and_y_keeping_its_remainder`, `solid::side_push_moves_by_overlap_depth`
- Заметённые AABB двух движущихся тел пересекаются ложно: тела касаются одного места в разное время тика. Поэтому контакт — сенсор на пиксельном шаге. → тесты `actor::contact_follows_pixel_path_not_swept_box`, `platformer::crossing_sweeps_with_touching_ends_do_not_kill`
- Сенсор ловит вход только движущегося тела: враг, вошедший в стоящего игрока, виден лишь проверкой пересечений в конце тика. → тест `platformer::enemy_walking_into_standing_player_kills`
- Клетка тайловой карты — `div_euclid`, не `/`: деление округляет к нулю, и `−1 / 18 = 0` кладёт отрицательную координату в клетку 0. → тест `tilemap::negative_coords_floor_into_outside_cells`
- Туннелирование быстрых тел: ограничение скорости и подшаги, CCD позже. → тест `actor::fast_fall_does_not_tunnel_through_one_pixel_tile`; будущее: CCD для тел без пиксельного шага

### Физика 3D

- Тензор инерции хранится в осях тела, в мир — `R·I⁻¹·Rᵀ`: диагональ без поворота годится только в покое, после поворота тело получает момент не той оси и кувыркается. → тест `body::inertia_world_swaps_axes_after_quarter_turn`
- Гироскопический член явным Эйлером накачивает энергию вращения: кувыркающееся тело раскручивается само. → тест `body::free_rotation_does_not_pump_momentum_or_energy`
- Вырожденный треугольник (`|e1×e2| < 1e-8`, такие есть в `roadStart` и мостах Racing Kit) даёт NaN в нормали, а через контакт — в теле, и машина исчезает без ошибки. `StaticWorld::new` не кладёт его в сетку, индекс сохраняется. → тест `world::degenerate_triangle_gives_no_hit`
- Внутреннее ребро шва (две детали встык, общая сторона двух треугольников квада): ближайшая точка на ребре соседа даёт нормаль с боковой составляющей, и сфера подпрыгивает на стыке, а машина рыскает. Поэтому на внутреннем ребре берётся нормаль грани. Вершину считать внутренней по двум рёбрам её треугольника нельзя: у угла шва оба ребра треугольника внутренние, а сама вершина на краю. → тесты `world::coplanar_seam_of_two_pieces_pushes_straight_up`, `world::inner_vertex_of_seam_pushes_up_and_outer_corner_does_not`, `world::vertices_within_weld_merge_and_farther_do_not`
- Двусторонний контакт: сфера, центр которой ушёл под плоскость дороги, выталкивается вниз, и её продавливает сквозь дорогу. → тест `world::sphere_behind_face_gives_no_contact`
- Запрос с огромным или бесконечным AABB (радиус колеса `inf`, NaN из тела) перебирал ячейки по всему диапазону `i32`: игра висла без ошибки. Диапазон обрезается занятыми ячейками сетки, а колесо с нулевым или бесконечным радиусом — ошибка машины: луч бесконечной длины перебирает весь мир. → тесты `world::infinite_query_visits_only_occupied_cells`, `car_config::flat_or_infinite_wheel_is_error`
- Вершина дальше ~2·10⁶ м насыщает ключ ячейки склейки до границы `i32`, и сумма с соседом в debug паниковала переполнением в `StaticWorld::new` — игра падала на загрузке трассы с дальним декором. Соседи берутся `saturating_add`, `racing` ещё и ограничивает позицию декора. → тесты `world::welder_beyond_i32_keys_saturates_without_overflow`, `track::huge_cell_or_level_and_non_finite_decor_fail`
- T-стык (вершина одной детали посреди ребра другой) не склеивается, ребро на нём внешнее — на таком шве сфера снова подпрыгивает. В Racing Kit T-стыки есть только на боковых швах травы. → будущее: детали с T-стыками на дороге потребуют разрезания рёбер
- Выталкивание через скорость (Баумгарте) оставляет телу скорость от мира после выхода из глубины: машина подпрыгивает после приземления. Поэтому глубина правится сдвигом `pos`, скорость — только импульсами. → тесты `solve::push_out_moves_pos_but_not_velocity`, `solve::fall_without_restitution_does_not_bounce`
- Упругость без порога отражает и сближение `g·dt` от тяжести на каждом подшаге: стоящее тело дрожит. → тесты `solve::restitution_only_above_threshold`, `solve::approach_exactly_at_threshold_does_not_bounce`, `solve::box_on_plane_rests_without_drift_or_energy_gain`
- Проскок сквозь барьер: контакт сферы ловится, только пока центр перед гранью, — за подшаг тело должно сдвигаться меньше радиуса. При 1/240 с и r = 0,3 это до 72 м/с, барьер 0,48 м держит удар на 50 м/с; крупнее шаг или мельче сфера — проскок без ошибки. → тест `solve::fast_ball_does_not_pass_thin_wall`
- Импульс между избыточными опорами (четыре сферы на плоскости) делится неоднозначно, и порядок контактов менял рыскание после удара на ~8 % — порядок обхода ячеек сетки стал бы физикой. Контакты сортируются по точке. → тест `solve::contact_order_does_not_change_result`

### Звук

- В звуковом колбэке нет аллокаций, блокировок и ввода-вывода. Иначе будет треск. → тест `audio::callback_neither_allocates_nor_frees` (`allocation-counter`: свой аллокатор требует `unsafe`, `assert_no_alloc` — BSD-1-Clause вне `deny.toml`); блокировки и ввод-вывод — ревью; запуск: слух и `audio cb` в логе
- Частота файла ≠ частоте устройства: ресемплинг при загрузке, иначе меняется высота звука. → тест `decode::resample_44100_to_48000_interpolates_linearly`, `assets::sound_is_resampled_to_assets_rate`
- `Stream` объявлен в `Running` раньше `ctx`: поля дропаются по порядку объявления, и колбэк останавливается до освобождения `Assets`. Обратный порядок — после `Assets` последний `Arc` звука остаётся у голоса и освобождается в колбэке. → ревью
- Последний `Arc` звука не должен умирать в колбэке: освобождение — аллокатор на аудиопотоке. Перезагрузка кладёт заменённый звук в `retired` навсегда; выгрузка обязана откладывать освобождение до ухода голоса. → тест `assets::changed_sound_replaces_frames_and_retires_old`
- Процедурный звук — только append-only через `Assets::add_sound`: `Sound`, собранный игрой и выброшенный после `play`, освободил бы последний `Arc` в колбэке. Поэтому `Sound` снаружи движка не собрать. → тест `assets::added_sound_gets_new_handle_with_same_frames`
- Перезагрузка звука не трогает играющие голоса: музыка остаётся старой до следующего `play_music`. → принято: дев-инструмент
- `set_sample_rate` после `load_sound` оставил бы в кэше звуки чужой частоты — другая высота без ошибки; поэтому устройство открывается до `Game::init`. → тест `assets::sample_rate_after_load_panics_in_debug`; порядок в `app.rs` — ревью
- Голоса заняты — новый эффект отбрасывается со счётчиком, играющий не крадётся: обрыв голоса посреди волны — щелчок. → тесты `mixer::effect_beyond_voices_is_dropped_and_music_keeps_its_slot`, `mixer::effect_on_full_pool_does_not_steal_a_playing_voice`
- Огибающая — в аудиофреймах, одна на L и R: по сэмплам каналы затухали бы со сдвигом. У звука короче двух огибающих fade-in и fade-out не складываются, берётся минимум, иначе пик выше громкости. → тест `mixer::fade_ramps_64_frames_equally_in_both_channels`
- Потерянный при полной очереди `Stop` — вечный мотор. `Stop` и последний `Set` слота ждут в `Audio` и досылаются в начале каждого вызова и в `flush` раз в кадр. `LoopId` несёт поколение слота: опоздавшие `Set` и `Stop` прежнего голоса микшер не применяет к новому. → тесты `audio::stop_waits_out_full_queue_until_flush`, `audio::stop_waits_out_full_queue_until_next_call`, `audio::set_loop_coalesces_to_last_while_queue_is_full`, `mixer::loop_commands_of_other_generation_or_slot_are_ignored`; вызов `flush` в `app.rs` — ревью
- NaN в громкости или скорости голоса попадает в общий буфер и глушит весь звук, а плавный переход громкости от NaN не выходит: голос молчит, пока его не остановят. Микшер чистит NaN, ∞ и знак на входе. → тесты `mixer::non_finite_or_negative_volume_is_silence_and_does_not_stick`, `mixer::loop_rate_is_clamped_to_zero_and_max`
- Сведение в моно по равенству громкостей каналов вместо флага команды даёт скачок образа на оси: стерео-файл прямо спереди играет как есть, а чуть сбоку — моно. → тест `mixer::stereo_file_image_is_continuous_across_center`
- На стыке цикла музыки огибающей нет: затухание к стыку слышно как провал раз за круг. Шов без щелчка — дело файла (loop-ready). → тест `mixer::music_loops_with_fade_in_only_on_first_start`; шов — слух
- Гармоника цикла мотора `racing` выше `sample_rate / 2 / MAX_RATE` на большом `rate` уходит за Найквист и заворачивается в нестройный писк без ошибки. Синтез берёт только гармоники ниже, а оборот — целым числом отсчётов, иначе шов цикла даёт утечку по всему спектру. → тест `engine_sound::synth_has_no_harmonics_that_alias_at_max_rate`

- Клик захвата длиннее кадра, а `grabbed` приходит кадром позже: зажатая с захвата кнопка в `shooter` дала бы выстрел. Стреляет только кнопка, нажатая при захвате. → тест `shooter::hitscan_needs_grab_and_skips_dead_enemy`
- Скольжение круга `shooter` по стенам сравнивает позицию с гранями клеток: при радиусе, не точном в двоичном (0,2), упор по одной оси оставляет круг в соседней клетке на ошибку округления, и та выталкивает его сквозь стену по другой оси. Клетка, перекрытая по оси хода, в `slide` пропускается; у `maze` радиус 0,25 точен в двоичном. → тест `shooter::player::corner_is_not_passed_at_full_speed`
- Атлас шрифта — только ASCII, остальное рисуется `?`: HUD `racing` по-английски, а русская ошибка трассы — в окне egui с тем же шрифтом. Спрайтовым текстом она молча вышла бы строкой вопросов. → тест `racing::track_error_shows_in_window_with_cyrillic_font`
- «Не туда» в `racing` — по направлению детали под центром масс (от её входа к выходу), не к следующему чекпоинту: машина, задом обогнувшая поворот, ехала бы к нему «правильно». → тест `race::wrong_way_follows_piece_under_car_not_next_checkpoint`
- Прямоугольник чекпоинта `racing` поднимается до ближайшей дороги выше в клетках стыка, без неё — без предела. С высотой в полосу уровня (2 м) быстрый прыжок с `roadRamp` перелетал чекпоинт за трамплином, и круг молча не засчитывался; без предела под мостом машина сверху засчитала бы чекпоинт нижней дороги. → тесты `track::checkpoint_without_road_above_counts_any_jump_height`, `track::bridge8_checkpoints_stop_under_bridge_deck`, `autopilot::hatchback_laps_ramp_jump`
- Торец барьера `roadRampLong` прямо за поворотом ловит машину, срезавшую поворот, и она стоит у него без ошибки. На стартовых трассах между поворотом и рампой — прямая. → тест `autopilot::race_future_laps_bridge_eight`, `autopilot::every_car_laps_every_track`
- Редактор `racing` перестраивает `Layout` после каждой правки и отмены: пикинг декора идёт лучом по его `StaticWorld`, и по старому `Layout` декор вставал бы на прежнюю трассу — на снятую дорогу или сквозь новую. → тест `editor::picking_follows_layout_after_edit_and_undo`
- Внешнее изменение трассы при `dirty` черновике редактора `racing` черновик не трогает, а ставит флаг до «Загрузить с диска» или «Сохранить»; «Новый» и открытие другой трассы при `dirty` ждут «Отбросить» в панели. Иначе несохранённые правки молча пропали бы. → тесты `racing::external_change_keeps_dirty_draft_and_replaces_clean_one`, `racing::new_and_open_wait_for_confirmation_while_dirty`
- Заезд `racing` идёт по последней цельной трассе — с диска или по черновику, с которым вышли по F1; трасса с рваной цепочкой открывается только в редактор, а при запуске игры — паника. Лучший круг и призрак сбрасываются только при смене этой трассы: F1 без правок их оставляет. → тесты `racing::f1_races_whole_draft_unsaved_and_resets_best_lap_only_after_edit`, `racing::f1_with_broken_chain_stays_in_editor_naming_piece`
- Ось деталей пути `trains` — таблица середин сечений головок рельсов меша Train Kit, а не дуги: окружность расходится с рельсами до 0,11 м, и тележки съехали бы с рельсов при зелёных тестах формулы. Корень GLB путей стоит на y = −1, подъём на 1 возвращает верх рельса на `RAIL_TOP`. → тесты `piece::rail_heads_run_along_axis`, `piece::rail_top_after_transform`
- Граф пути `trains` поворачивает концы деталей точной перестановкой координат и сравнивает стыки без допуска, а модель детали рисуется через `Mat4::from_rotation_y`. Знак поворота, разошедшийся между ними, молча увёл бы поезд мимо рельсов; неточный конец детали молча разорвал бы стык в два тупика. → тесты `track::rail_transform_follows_graph_axis`, `piece::ends_match_kit_table`
- Хвост состава `trains` идёт по своему списку рёбер, а не по `Track::next`: по графу стрелка, переведённая под составом, молча увела бы хвост на другую ветку, и состав разорвался бы. Задний ход переворачивает список на время шага, и голова идёт тем же списком. → тесты `train::switch_thrown_under_train_keeps_tail_on_its_branch`, `train::reverse_leads_with_tail_and_keeps_route_order`
- Зазор `GAP` между машинами `trains` подобран под повороты карты (`corner-large`, S-деталь): на `corner-small` кузова соседних машин при нём пересекаются, и карта с этой деталью молча показала бы вагоны друг в друге. → тесты `train::neighbour_bodies_never_touch_on_level01`, `train::neighbour_bodies_never_touch_on_bends_both_ways`, `train::corner_small_is_too_sharp_for_gap_and_not_on_map`
- Стрелка впереди `trains` ищется по последнему направлению хода `Train::reverse`, а не по знаку скорости: упор обнуляет скорость, и E после остановки задним ходом перед стрелкой молча перевёл бы стрелку впереди головы. → тест `switch::key_finds_nearest_switch_ahead_by_last_direction`
- Пересборка в депо `trains` ставит состав в начало депо заново, а газ при открытом депо выключен: иначе состав уехал бы с открытой панелью, и следующая команда панели молча перенесла бы его скачком обратно. Открывает депо Tab только у стоящего состава целиком на рёбрах пути депо. → тесты `trains::depot_is_open_at_start_and_blocks_gas`, `trains::tab_opens_depot_only_for_standing_train_on_depot_path`, `trains::rebuild_puts_consist_at_depot_start`
- Сцена `trains` интерполирует между тиками и камеру, и машины по одному `alpha` от состава прошлого тика: с одной камерой при частоте кадров выше `TICK_HZ` поезд молча дрожал бы на экране. Ветки стрелки перекрываются, а земля лежит под плитками: активная ветка поднята на `SWITCH_LIFT`, земля опущена на `GROUND_DROP`, иначе на одной высоте они мерцали бы. → тесты `trains::camera_is_isometric_and_follows_consist_middle_between_ticks`, `trains::active_branch_is_lifted_and_inactive_dimmed`, `trains::ground_below_grass_sun_lights_sides_facing_camera`

Чистая логика (ECS, коллизии, микшер) покрывается юнит-тестами, рендер и звук проверяются играми и отладочным оверлеем. Достаточность тестов меряют покрытие строк с порогом (`make cov`, только вверх; `app.rs`, `renderer.rs` и `audio/device.rs` — склейка, вне замера; чистая логика поверхности вынесена в `surface.rs` и меряется) и мутанты (`make mutants`, выживших нет вне исключений с причиной).
