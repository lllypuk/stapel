## Текст вне ASCII молча становится '?'
- Doing: выбирал язык HUD для игры на русском запросе.
- Expected: по `load_font` и JetBrains Mono в AGENTS.md — что кириллица нарисуется, в шрифте она есть.
- Happened: `text.rs`: «Символ вне ASCII 32..=126 рисуется как '?'». В AGENTS.md и логах об этом ни слова, а `texts` в отчёте покажет исходную строку, так что отчёт такую подмену не заметит.
- Cost: один проход по исходникам; HUD сделан на английском.
- Workaround: только ASCII.
- Wanted: docs change: строка в разделе про шрифты; лучше engine change: атлас с заданным набором символов.
Исход: правка доков — Task 15 (строка про ASCII и подмену на `?` в раздел «Assets» `docs/agents/AGENTS.md`; фраза совпадает с `text.rs`, проверено). Первый исход («потребность не доказана») неверен: агент сменил язык HUD из-за движка, а английский публичный слой не обязывает игрока читать по-английски. Новый исход: доки сейчас (Task 15); правка движка сейчас (Task 19: `warn` один раз на отсутствующий символ, `texts` хранит исходную строку, подмена описана); атлас с заданным набором символов — пункт этапа 11. Полный Unicode-shaping не запрашивается.

## Сценарий нельзя привязать к состоянию игры и снять отчёт без PNG
- Doing: расставлял клики постройки в `win.toml` так, чтобы монет хватало к нужному тику.
- Expected: способ увидеть, когда монет хватит, без подбора вслепую.
- Happened: сценарий знает только тики, отчёт есть только в снимках, каждый снимок пишет PNG. Сдвиг одного клика меняет всю экономику дальше: дважды оставался отказ (`refused_builds: 1`), башен 9 вместо 10.
- Cost: 2 неудачные попытки, затем 9 прогонов со снимком каждые 15 тиков (около 830 PNG за прогон).
- Workaround: скрипт вне репозитория подбирал тик каждой башни по отчёту предыдущего прогона.
- Wanted: engine change: `report_every = N` без PNG или ключ `--no-png`.
Исход: правка доков — Task 16. Утверждение записи неверно наполовину: `run_script(.., None)` отдаёт отчёты снимков без PNG (`runner.rs`, PNG пишется только при `out`), и README это говорит, но AGENTS.md умалчивает; Но CLI связывает JSON с PNG, так что для CLI трение настоящее. Новый исход: доки сейчас (Task 16) и малая правка движка `--no-png` (Task 20). Условия на состояние игры в TOML — «не чиним»: чувствительность к таймингу в replay нормальна.

## Критерии и сверка

Абзац: Tower defense (враги идут по тропе волнами, башни за монеты по клику, 10 жизней, победа после пятой волны). Критерии зафиксированы до запуска и сессии не передавались. Проверка независимая: сценарии прогнаны заново из каталога игры на rev `50397c3`, по два прогона в новые каталоги, PNG просмотрены, код источников полей `report` прочитан (`sim.rs`: `kills` растёт только в `hit`, `phase = won` только в `check_cleared` после опустевших очереди и поля, `lives` падает только в `move_enemies`).

Зафиксированы до запуска холодной сессии, ей не передаются.

Абзац: Tower defense: враги идут по тропе к базе волнами, игрок кликом ставит башни за монеты, у базы 10 жизней, победа после пятой волны.

1. Сборка в каталоге игры из git-зависимости на закреплённый rev, без path-зависимости и правок движка.
2. Цель: сценарий доводит игру до победы. В отчёте номер волны 5 и признак победы, жизней больше 0; на снимке видно состояние победы.
3. Поражение: сценарий без защиты доводит жизни до 0. В отчёте признак поражения и признака победы нет; на снимке видно состояние поражения.
4. Ход игры: на снимке середины игры видны тропа, враги на ней и башня там, куда был клик.
5. Экономика: постановка башни уменьшает монеты в отчёте, убийство врага увеличивает.
6. Жизни уменьшаются, когда враг доходит до базы; в начале их 10.
7. Башню нельзя поставить без монет: число башен в отчёте не растёт.
8. Прогоны сценария заново из её каталога дают тот же отчёт и те же PNG.
9. У ассетов есть источник и лицензия; `FRICTION.md` заполнен.

## Что проверка не покрыла

Вручную, пользователем:
- реальная мышь в обычном окне;
- resize и HiDPI;
- letterbox;
- клетка клика совпадает с призраком постановки;
- потеря фокуса и возврат;
- рестарт после победы (`rules` покрывает рестарт только после поражения).
